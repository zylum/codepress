# Release: v0.5.0 — the lifecycle becomes data

## Theme
Rules that were prose become rules a machine checks.

## Overview
CodePress now has one enforceable definition of how work moves. The statuses, the allowed transitions, and the gates each transition requires live in `.codepress/system/schema/lifecycle.yaml`; `codepress lint` is the single enforcement point for git hooks and CI; and `codepress galley move` runs the same gates. A galley is any bounded task with a contract, gates and a record of how it went — nothing in the schema assumes code.

## Galleys included

| Galley | Description |
|---|---|
| enforced-acceptance | Bound acceptance criteria, `codepress check`, gated moves, independent Verdict |
| schema-and-lint | Lifecycle as data, `codepress lint`, structured signals, plan-change log, one version marker, hook |

## What's new
- **Seven galley statuses:** `proposed → shaped → building → verifying → done`, plus `killed` and `superseded`. Approval is a gate on `shaped → building` (`codepress galley approve`), not a status. Slugs: `open → building → closed | dropped`.
- **Gates as data:** every transition lists its requirements. `done` needs all slugs settled, `## Evidence`, an independent Verdict, and `learned.md`.
- **`codepress lint`:** retired statuses, illegal transitions (against `HEAD` or `--base`), terminal galleys missing evidence / review / `learned.md`, schema violations, version-marker disagreement, and **drift** — `slug:<x> done` commits whose acceptance boxes were never ticked. Waivers (`--force --reason`) downgrade failures, so `--no-verify` is never needed.
- **Slug delivery fields:** `domain`, `tier` (`plan | build | mechanical`), `risk`, `needs_review`, `escalate_after`, `autonomy`.
- **Structured signals** (`failure_class`, `caught_by`, `should_have_been_caught_by`, `action`, `status`) and a per-galley **plan-change log**.
- **`codepress hook install`:** pre-commit lint + verify gates; finds a tool environment in fresh git worktrees (`CODEPRESS_ENV`, `hook-env:`, the main worktree's venv).
- **`codepress status --json --galleys`:** per-galley state with `next_action`, who it `needs`, `stalled`, and last activity that counts commits naming the galley.
- **`codepress migrate-status`:** dry-run plan, then `--apply`, from the documented legacy mapping.
- **One version source:** the marker in `system/codepress.md`. The CLI derives its version from it; `codepress upgrade` no longer overwrites `codepress.md`, it moves the marker.

## Notes
**Breaking.**
- Retired status values (`shaping`, `approved`, `delivering`, `review`, `rework`, `ready`, `complete`, `delivered`, `released`, `learned`, `archived`; slug `complete`, `done`, ...) fail `codepress lint`. Galleys still on a retired status keep the old `galley move` gates until migrated.
- `lint` needs `python3` 3.8+ (standard library only).

**Migrating a project.**
1. `codepress upgrade`
2. `codepress migrate-status` — review the plan, especially the **judgment calls** (`ready`, `rework`, `complete`, `delivered`, `archived`) — then `--apply`
3. `codepress lint`, fix what it reports
4. `codepress hook install`

Terminal galleys that predate the schema are marked `legacy: true` and are not gated retroactively. Mapping table: `docs/lifecycle.md`.
